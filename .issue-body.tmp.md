## Summary

Swagger documentation is inconsistent across controllers. Several endpoints have no XML documentation at all, and many that do are missing `<param>` and `<response>` tags. `ProjectsController` is the worst offender.

## Current state

**`src/SheetMusic.Api/Projects/ProjectsController.cs`** — no controller-level `<summary>`, and 7 of 8 actions have no XML docs at all:

- `GET /projects`
- `GET /projects/{projectIdentifier}`
- `GET /projects/{projectIdentifier}/sets`
- `POST /projects`
- `DELETE /projects/{projectIdentifier}/sets/`
- `DELETE /projects/{projectIdentifier}`
- `PUT /projects/{projectIdentifier}`

Only `POST /projects/{projectIdentifier}/sets` has a `<summary>`, and it still lacks `<param>` and `<response>` tags. All actions also return `IActionResult` rather than `ActionResult<T>`, so Swagger cannot infer the response schema either.

**`src/SheetMusic.Api/Users/UsersController.cs`** and **`UsersV1Controller.cs`** — have `<summary>` tags but are missing `<param>` and `<response>` documentation; they rely on `[ProducesResponseType]` only for success codes.

**`src/SheetMusic.Api/Parts/PartsController.cs`** and **`Controllers/CategoriesController.cs`** — good reference examples; use these as the target standard.

## Scope

Bring every REST endpoint up to the standard already set by `PartsController` and `CategoriesController`:

- Controller-level `<summary>` describing the resource and any privilege requirements.
- Per-action `<summary>` describing what the endpoint does.
- `<param>` for every route/query/body parameter.
- `<response code="...">` for every status code the endpoint can produce, including `400`, `401`, `403` and `404` where applicable.
- Return `ActionResult<T>` instead of `IActionResult` in `ProjectsController` so response schemas show up in Swagger.

## Acceptance criteria

- [ ] Every public action across `ProjectsController`, `SheetMusicController`, `PartsController`, `CategoriesController`, `UsersController` and `UsersV1Controller` has a `<summary>`, `<param>` tags and `<response>` tags.
- [ ] `ProjectsController` actions return `ActionResult<T>` with the correct view model type.
- [ ] The generated Swagger document shows a description and typed response schema for every operation.
- [ ] No new build warnings from missing XML comments.
